# SalesGrid Android App (Capacitor)

The Android app is a thin native shell (`apps/mobile/`) around the **deployed** SalesGrid web
application. It does not contain a copy of the UI or any business logic: the WebView loads
`SALESGRID_SERVER_URL` over HTTPS, and everything (pages, API, auth, realtime) is served by the
same Next.js + Socket.IO server as the browser version.

## 1. Audit summary (why "hosted" mode)

| Area | Finding | Consequence for Capacitor |
|---|---|---|
| Next.js | 14.2.35, App Router, `force-dynamic` server-rendered layouts that load the session from an httpOnly cookie | Cannot be exported as static files (`output: 'export'` would drop server rendering, middleware and Route Handlers). A bundled offline copy is not possible without rewriting the app. |
| Server Actions | None (`'use server'` is not used) | Nothing to adapt. |
| Middleware | Role redirects from the signed session cookie | Works unchanged in the WebView (same origin). |
| API | 60+ Route Handlers on the same origin, cookie or Bearer auth | Same-origin cookie auth works in the WebView; no CORS changes needed. |
| Realtime | Socket.IO on the same server, cookie handshake, same-origin check | Works unchanged (WebView origin = server origin). |
| Auth | JWT in httpOnly `sg_session` cookie, DB check on every request, server-side revocation | Unchanged. The app never sees or stores the token. |
| GPS | `navigator.geolocation` (foreground, while on duty) | Works in the WebView; Capacitor maps the web prompt to the Android location permission. |
| Files | `<input type=file capture>` for receipts; PDFs/CSV opened in new tabs | Camera works through Capacitor's file chooser. The WebView cannot show PDFs or handle downloads, so documents go through the Android share sheet (see §5). |
| Tenancy | Single-tenant (no tenant model); isolation is role/team/ownership based on the server | Unchanged — all checks stay server-side. |

**Decision**: Capacitor "hosted" mode (`server.url`). Web changes go live by deploying the server;
only native changes need a new APK (§7).

## 2. Layout

```
apps/mobile/
  capacitor.config.ts        app id com.salesgrid.app, name, server URL, splash, system bars
  package.json               Capacitor 8 + plugins (exact versions), build scripts
  www/index.html             fallback that redirects to the server
  www/offline.html           shown when the server can't be reached at launch (retry + auto-retry)
  assets/                    icon/splash sources (generated by scripts/make-assets.mjs)
  scripts/check-config.mjs   validates SALESGRID_SERVER_URL, writes www/app-config.js, pings /api/health
  android/                   generated Android Studio project (committed)
.github/workflows/android.yml  CI build: debug APK, signed release APK when secrets exist
```

Web-side native integration lives in the main app and is loaded **only inside the app**
(`window.Capacitor.isNativePlatform()`), so browser users download none of it:

- `src/lib/native/bridge.ts` — back button, splash hide, pause/resume events
- `src/lib/native/documents.ts` + `src/components/shared/DocLink.tsx` — PDFs / CSV / uploaded files
- `src/lib/native/biometric.ts` + `src/components/native/DeviceLock.tsx` / `BiometricSetting.tsx`
- `src/components/native/NativeShell.tsx` — offline banner (console/login), "update required" gate
- `src/lib/native/logic.ts` — the pure decisions (unit-tested)

## 3. Environment variables

**Android build** (`apps/mobile`, at `npm run sync` / build time):

| Variable | Required | Notes |
|---|---|---|
| `SALESGRID_SERVER_URL` | yes | Deployed server, `https://…`. Baked into the APK. |
| `SALESGRID_ALLOW_HTTP` | no | `true` only for a local dev build against `http://<LAN-IP>:3000`. Cleartext is allowed in **debug** builds only (`app/src/debug` network config); release builds are HTTPS-only. |
| `SALESGRID_VERSION_CODE` / `SALESGRID_VERSION_NAME` | no | Android versionCode (integer, increase for every APK you hand out) / display version. Default `1` / `1.0.0`. CI uses the run number. |
| `SALESGRID_KEYSTORE_PATH`, `SALESGRID_KEYSTORE_PASSWORD`, `SALESGRID_KEY_ALIAS`, `SALESGRID_KEY_PASSWORD` | for signed release | Or put `storeFile`, `storePassword`, `keyAlias`, `keyPassword` in `apps/mobile/android/keystore.properties` (git-ignored). Never commit keystores or passwords. |

**Server** (main app):

| Variable | Notes |
|---|---|
| `ANDROID_MIN_BUILD` | Optional. Apps with a lower versionCode show a blocking "Update required" screen. |
| `ANDROID_LATEST_BUILD`, `ANDROID_UPDATE_URL` | Optional. Shown with the update screen (`ANDROID_UPDATE_URL` = Play Store / download page). |
| `DEV_QUICK_LOGIN` | Development only (see §6). Ignored when `NODE_ENV=production`. |

## 4. Setup and build commands

Prerequisites: Node 22, JDK 21, Android SDK (API 36) — Android Studio installs it.

```bash
cd apps/mobile
npm ci
export SALESGRID_SERVER_URL=https://salesgrid.yourcompany.com
npm run sync                 # validate config, copy config + plugins into android/
npm run open                 # Android Studio (run on a device from there), or:
npm run build:debug          # android/app/build/outputs/apk/debug/app-debug.apk
npm run build:release        # signed when the signing variables/keystore.properties exist
npm run bundle:release       # .aab for Google Play
```

Install a debug APK on a USB-connected phone: `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`.

Create a release keystore once (keep it and its passwords safe — losing it means you cannot update the app):

```bash
keytool -genkeypair -v -keystore salesgrid-release.jks -alias salesgrid -keyalg RSA -keysize 4096 -validity 10000
```

Regenerate icons/splash after changing the mark: `node scripts/make-assets.mjs && npm run assets`.

**Local development against your laptop**: run `npm run dev` in the repo root, then
`SALESGRID_SERVER_URL=http://192.168.x.y:3000 SALESGRID_ALLOW_HTTP=true npm run build:debug`.
Note: with `COOKIE_SECURE` defaulting to off in development this works over http; production must be HTTPS.

**CI** (`.github/workflows/android.yml`): set the repository variable `SALESGRID_SERVER_URL`; for a signed
release APK also the secrets `ANDROID_KEYSTORE_BASE64` (`base64 -w0 salesgrid-release.jks`),
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. APKs are attached to the workflow
run as artifacts. Without the variable the workflow only checks that the project compiles.

## 5. Native behaviour

| Feature | Behaviour |
|---|---|
| App id / name | `com.salesgrid.app` / SalesGrid. Change the id **before** the first store release (`appId` in `capacitor.config.ts` and `applicationId`/`namespace` in `android/app/build.gradle`); it cannot change afterwards. |
| Icon / splash | SalesGrid mark on navy, adaptive icon; splash hides as soon as the page is ready (max 2.5 s). |
| HTTPS origin | The WebView origin is the server's HTTPS origin; release builds refuse cleartext; mixed content blocked. External links (Google Maps directions, `tel:`) open in the matching Android app. |
| Back button | Closes the open sheet / navigation drawer first; otherwise goes back; on home screens (`/field`, `/dashboard`, `/login`) the app is minimised, not closed, so an open shift keeps tracking while the app stays in memory. |
| Network errors | Server unreachable at launch → `offline.html` with *Try again* and automatic retry when the connection returns. While open: the field app's existing offline queue (orders, collections, expenses, visits, GPS) keeps working; console and login show an offline banner. |
| GPS | Same tracker as the web app (foreground, while on duty, adaptive sampling). Android asks for location permission on *Start day*. No background-location permission is requested: tracking pauses when the app is closed or the phone kills it, exactly as in the browser, and gaps are shown in Route History. |
| Camera / files | Receipt photos use the system camera/file picker. PDFs (receipts), CSV exports and uploaded files open through the Android share sheet (*Open with* a PDF viewer, Drive, WhatsApp…), downloaded with the user's session — no tokens in URLs. |
| Notifications | In-app realtime notifications and toasts work as on the web (Socket.IO). **Push notifications (app closed) are not implemented**: no existing module sends push, and it would need a Firebase project (`google-services.json`) plus server-side FCM sending. |
| Biometric unlock | Optional, per user per phone (*More → Profile → Security on this phone*), shown only if the phone has a fingerprint/face sensor or screen lock. Locks the app on start and after 5 min in the background; *Sign out* is always offered. It is a device lock in front of the server session — it never stores passwords or tokens and does not replace server authentication. Turned off for that user on sign-out. |
| Updates | Web changes: deploy the server, users get them on next app open. Old native builds can be retired with `ANDROID_MIN_BUILD`. |

## 6. Quick access login (web and app)

- **Remember me** (login form): on → 7-day persistent session (the legacy behaviour; default in the
  Android app); off → 12-hour token in a session cookie that is dropped when the browser or app process
  closes. The choice is kept when the session is renewed. API clients that don't send `remember` keep the
  legacy 7-day session.
- With Remember me, the **sign-in name** (email / phone / employee code — never a password or access code)
  is remembered on the device to prefill the form; *Not you?* forgets it, and *Sign out of all devices*
  clears it.
- **Valid session → straight to the right home screen**: opening the app or `/login` with a valid
  session goes to `/dashboard` (admin/manager) or `/field` (salesperson); an expired or revoked
  session lands on the login page with a message.
- **Sign out** clears the session cookie (server response), the biometric preference and the field
  app's cached data; *Sign out of all devices* also revokes every session server-side.
- **Development quick login**: `DEV_QUICK_LOGIN=true` with `NODE_ENV` ≠ `production` shows one-tap
  sign-in buttons for active users of the local database. The server issues a normal session (same
  cookie, role permissions and audit log). It replaced the old demo buttons, which shipped the seed
  passwords inside the login page's JavaScript on every build. Production builds ignore the variable
  (asserted by an E2E test); never enable it on a server reachable by untrusted people.
- No passwords, tokens or credentials are in the source, the web bundle or the APK (the APK contains
  only the server URL). An integration test scans the login page and every script it loads for the seed
  passwords.

## 7. What needs a new APK

| Change | New APK? |
|---|---|
| Any page, component, style, text, API route, business rule, permission, report | **No** — deploy the server |
| Server URL / domain | Yes |
| App id, name, icon, splash, colours of the native splash/system bars | Yes |
| Android permissions (e.g. adding background location or push) | Yes |
| Adding/removing/upgrading a Capacitor plugin or Capacitor itself | Yes (plugin JS also ships with the web app; keep `apps/mobile` and root versions identical) |
| `capacitor.config.ts`, `offline.html`, Gradle/SDK versions, signing key | Yes |

Bump `SALESGRID_VERSION_CODE` for every distributed APK, and raise `ANDROID_MIN_BUILD` on the server
when an old shell must stop working (e.g. after a plugin change the web code depends on).
